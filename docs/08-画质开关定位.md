# 08 - 画质开关：从 GC 符号定位 Xbox 版的渲染全局变量

> 日期：2026-10-07。前置文档：[07 RenderDoc 帧捕获分析](07-RenderDoc帧捕获分析.md)。
> 想法来源：`RECOMP_GL_SKIP` 是在 GL 层按尺寸丢掉 pass，游戏在主线程上照样做了剔除和准备。主线程才是瓶颈，所以应该在游戏自己的开关上关掉这些效果。

## 1. 结论

- **NFSU2 引擎内部有一组画质全局变量**，GC 版的符号里名字和默认值都看得到。EA 没有把它们做进菜单，只在**分屏双人**（`eGetCurrentViewMode() == 3`）时，每帧切换到低配：
  ```c
  // GC Speed.elf.c，主渲染函数，eBeginScene 之后
  if (eGetCurrentViewMode() == 3) { v5 = 0; v6 = 1; } else { v5 = 1; v6 = 0; }
  EnableMinimalEnvMap = v6;   DrawFancyCarShadow = v5;
  EnableLODZ          = v5;   DrawCarsReflections = v5;
  ```
- **Xbox 版里这段分屏低配逻辑至少不完整**：0x3CC5E8 在 Xbox 版里没有写入点（§4），所以切分屏不能保证触发同样的低配。
- **Xbox 版已定位并验证**：`0x3CC5E8 = DrawCarsReflections`。用 `RECOMP_POKE=0x3CC5E8:0` 关掉后，地面上的车身倒影消失（用户肉眼确认）。RenderDoc 显示 program 147 整组消失（48 个 draw，约 2000 个三角形），**每帧少约 50 个 draw（2%）**。单项收益很小。
- 其余开关还没在 Xbox 版定位到，见 §3。

## 2. 定位方法：.data 段的初始值指纹

GC 版和 Xbox 版是同一份引擎源码，同一个编译单元里的全局变量在 .data 段中**顺序相同，初始值相同**，只是基址不同。具体做法：

1. 在 GC 符号里找目标变量，记下它前后几个变量的初始值。尽量选浮点这类有辨识度的值。
2. 在 XBE 的 .data 段（raw 0x37E000 → VA 0x38BE60）里搜这串初始值。
3. 在 lifted C（`NFS 8/xbox/gen`）里看是哪些函数读这个地址，和 GC 版的调用点核对。

`DrawCarsReflections` 的例子：

| GC（VA） | 变量 | 初始值 | Xbox（VA） | 初始值 |
|---|---|---|---|---|
| 8046ED90 | `culldiv` | 27000.0 | 0x3CC58C | 27000.0 |
| 8046EDA8 | `DrawFancyCarShadow` | 1 | 待定（偏移和 GC 不一致） | — |
| 8046EDB8 | `WheelStandardWidth` | 0.184 | 0x3CC5E0 | 0.184 |
| 8046EDBC | `DrawCars` | 1 | 0x3CC5E4 | 1 |
| 8046EDC0 | `DrawCarsReflections` | 1 | **0x3CC5E8** | 1 |

核对调用点：Xbox 版里唯一读 0x3CC5E8 的函数是 `sub_00210480`。它的开头依次检查 `0x3CC5E8 != 0`、`0x3CC5E4 != 0`、`MEM32(0x428E34) == 6`，和 GC 版 `if (DrawCarsReflections && DrawCars && dword_803DBB48 == 6)` 一一对应。

注意事项：
- Xbox 版里 0x3CC5E8 **没有任何写入点**，分屏切换那段代码在 Xbox 版里写的不是它，或者被裁掉了。所以 `RECOMP_POKE` 把它固定住不会和游戏逻辑冲突。
- 在 Xbox 版里搜 `ScreenWidth=640, ScreenHeight=480` 加 `EnableEnvMap=1, EnableMinimalEnvMap=0, ...` 这整串，**没有命中**，说明这个编译单元的布局两版不同（Xbox 版的 640、480 后面紧跟的是 32、1、128……）。这几个开关要换方法定位，见 §4。

## 3. 开关清单（GC 名字和默认值）

| 变量 | 默认 | 作用（按调用点推断） | Xbox 地址 |
|---|---|---|---|
| `DrawCarsReflections` | 1 | 地面上的车身倒影 | **0x3CC5E8 ✅** |
| `DrawCars` | 1 | 车辆总开关（0 = 不画车，只用来调试） | 0x3CC5E4 |
| `EnableEnvMap` | 1 | 环境贴图总开关（128×128 那几个 pass，含它们自己的剔除） | 未定位 |
| `EnableMinimalEnvMap` | 0 | 环境贴图只画天空和光晕，不画场景（分屏时为 1） | 未定位 |
| `EnableLODZ` | 1 | 场景 LOD/Z 剔除路径（分屏时为 0，具体效果要实测） | 未定位 |
| `EnableRoadSpecular` | 1 | 路面高光 pass（一次额外的场景剔除和绘制） | 未定位 |
| `DrawFancyCarShadow` | 1 | 精细车影 | 未定位 |
| `ScenerySectionLODOffset` | 10 | 场景分区 LOD 偏移 | 未定位 |
| `TriggerEffectsOn` | 1 | 触发式特效 | 未定位 |
| `OnScreenRain` / `pTextureInfoRainDrop` | — | 屏幕雨滴 | 纹理指针 0x3EA640（docs/04） |
| `psMotionBlur` / `psGlowBloom` / `psDepthOfField` | — | 后处理（a4 = 100–103 分支） | 未定位 |

按 GC 主渲染函数的结构，`EnableEnvMap`、`EnableRoadSpecular`、`EnableLODZ` **每一项都意味着多一次 `SetupSceneryCullInfo` 和 `StuffScenery`**，也就是整套场景的剔除和提交。这几项的潜在收益比车身倒影大得多，因为它们省的是主线程。

## 4. 下一步：更快的定位手段

| 方法 | 做法 | 适用 |
|---|---|---|
| **结构匹配（静态）** | GC 主渲染函数的调用序列很有特征：`eBeginScene` → 读 ViewMode → `UpdateEnvironmentMapCameras` → `elBeginFrame` → 循环 `eGetView` → `SetupSceneryCullInfo(..., 2048)` / `(…, 0x4000)` / `(…, 4096)`。在 lifted C 里找"调用同一组函数、立即数相同"的函数，然后读它分支上测试的全局变量 | `EnableLODZ`、`EnableRoadSpecular`、`EnableEnvMap` |
| **字符串和资源交叉引用** | 例如 `RAINDROPTEST`、`Road Reflection`、`EnvMap %d` 这些字符串，从引用它们的函数顺藤摸瓜 | 雨滴、反射、环境贴图 |
| **运行时差分（动态）** | 停在同一画面，录两份 guest 内存快照，只改游戏状态（比如开关某个菜单项、切单人或双人），diff 出变化的 .data 字。也可以反过来：逐个 POKE 候选地址，看 `[fps]` 行的 draws/frame 怎么变 | 找不到调用点、或者有写入点的开关 |
| **覆盖率差分** | `NFSU2_PGO=gen`，单人比赛和分屏双人各跑一次，diff 被执行的函数集合，就能看出分屏模式多走或少走了哪些渲染函数 | 定位"分屏低配"那段代码 |

**切到分屏双人能不能直接触发低配？在 Xbox 版上大概率不能完整触发**：
- Xbox 版的 0x3CC5E8（`DrawCarsReflections`）**没有任何写入点**，所以 GC 版那段 `if (ViewMode == 3)` 每帧改写 4 个全局的代码，至少 `DrawCarsReflections` 这一行在 Xbox 版里不存在。可能这段逻辑是 GC 平台专属（GC 的 GPU 更弱），也可能 Xbox 版换了写法。
- 不过分屏仍然值得开一局抓帧：如果环境贴图 pass 变少，说明 Xbox 版有自己的低配路径，可以用运行时差分找出它改了哪些全局。双人模式要渲染两个视口，比较时要按每个视口、每个 pass 来对比，不能直接比总 draw 数。

## 5. 工具

- `RECOMP_POKE=0xVA:val[,...]`（`xbox_memory_layout.c`，最多 8 项）：每个 executor tick 把这个 guest 全局重新写成指定值。
- `[fps]` 日志行现在附带 `draws/frame`，真机上不抓 trace 也能看出某个开关砍掉了多少 draw。
- `tools/pc/rdoc.sh <名字> [ENV=..]`：在 RenderDoc 下启动，环境和 `run.sh` 一样，F12 抓帧，文件存到 `trace/<名字>_frameN.rdc`。手动在 qrenderdoc 里启动时要设的环境变量，见脚本里的 `env.sh`。
- `trace/rdc_frame.py`（转 XML 后，按 draw 跟踪状态）、`trace/rdc_cull.py`、`trace/rdc_dupe.py`（找镜像 pass）。trace/ 目录不在 git 里。
